# 人设管理

管理员可从账号菜单进入「人设管理」，按平台、作者、分类、公开状态或推荐标记查找作品。桌面和手机均可打开管理面板，核对当前公开版本、已发布快照、待审版本以及分页管理记录。

桌面直接显示搜索、平台和作品状态，作者、分类、推荐标记与排序在「更多筛选」中；手机在展开区集中选择条件。收起保留未提交输入，点击「筛选人设」才更新结果；「清空筛选」同时清除作者、分类等条件。输入有误时会展开对应字段并定位错误。

管理员可通过 `/api/v1/admin/personas` 按作者 ID、平台、分类和状态分页查询人设，通过 `/api/v1/admin/personas/:id` 读取单个人设的管理元数据。普通浏览使用有效管理员会话；账号变化、会话失效或权限撤销会立即阻断读取，响应禁止缓存。

列表每页最多 20 条，支持按更新时间、创建时间正序或倒序排列。搜索匹配作品名称、作者用户名或完整人设 ID，`%`、`_` 与反斜杠按普通文字处理。

状态筛选包含全部、当前公开、当前未公开、待审、作者隐藏和管理员下架。待审、隐藏与下架可与当前未公开重叠；恢复账号不会自动恢复作品，管理查询与公开资格使用实际作品状态分别判断。

名称和分类优先使用当前已发布版本的冻结资料，其次使用待审快照，最后使用私有草稿的元数据。列表和详情提供作者、平台、修订号、公开状态及版本指针，私有正文、图片授权证据、邮箱和账号凭据不进入这些响应。

完整查询参数与响应结构见 [OpenAPI 定义](openapi.json)，开发 API 也提供 `/api/v1/docs`。调用方可传 `X-Expected-Account` 核对实际登录账号；该请求头不能授予身份或权限，账号不一致返回 `409 CONFLICT`。

## 下架与恢复

管理员通过 `POST /api/v1/admin/personas/:id/moderation` 提交 `state`（`blocked` 或 `normal`）、具体处理理由 `reason` 及已核对的 `expectedRevision`，并提供 CSRF 令牌和 UUID 格式的 `Idempotency-Key`。调用前先读取管理详情，不能用草稿修订号代替人设修订号。

列表、详情、管理和处置操作使用有效的管理员会话。管理本人作品时仍须明确确认。

同一幂等键重复提交相同请求只处理一次；修改请求内容后复用该键返回 `409 CONFLICT`。修订号过期返回 `412 REVISION_CONFLICT`，应读取最新状态并由管理员重新核对，不能自动覆盖。每次写入或重试都会在事务内复核身份和权限。

下架和恢复同步追加处理记录与修订号，作者隐藏状态、私有草稿、版本正文及公开版本指针保持各自规则。恢复人设不会自动恢复已封禁的版本或改变作者的隐藏选择。

此接口的处置请求必须携带修订号与幂等键，旧调用方需要更新请求字段；响应仍使用通知结构，完成后重新读取详情核对实际状态。

在管理面板填写「上下架理由」后，选择准备操作并在弹层确认。提交使用当前有效管理员会话。冲突时先读取最新上下架状态，再明确采用该状态继续核对。

## 推荐标记

「官方作品」和「精选作品」是作品级运营标记，公开卡片、当前版本及公开历史版本详情随作品管理状态展示，作者的冻结正文、来源和版本记录保持各自规则。新增标记要求作品当前可公开；隐藏或下架作品可以解除已有标记。

通过 `PUT /api/v1/admin/personas/:id/curation` 提交两个标记值、`reason`、`expectedRevision` 和独立的 `Idempotency-Key`。标记操作使用有效管理员会话，管理自己的作品还需提交 `selfReviewConfirmed: true` 作为操作确认。理由最多 2,000 个 Unicode code point。

保存失败保留标记和理由，网络结果不明确时按原标识重试。修订冲突后不会自动覆盖，需读取并明确采用最新修订。取消勾选表示解除该标记。

首页从当前可公开的精选作品中，按首次发布时间倒序默认展示最多 4 条，点击「查看全部精选」可继续探索。可在 [首页展示](HOME_OPERATIONS.md) 调整数量、模块顺序和展示开关；没有精选作品时收起推荐区域。取消精选后不再进入推荐；隐藏或下架会立即失去公开资格，保留标记的作品在恢复公开资格后可重新进入结果。

## 批量操作

勾选至多 20 条作品后进入「管理所选人设」，选择下架、解除管理员下架或设置推荐标记，填写共同理由并核对本批作品。选择时的作品修订会保留，刷新列表不会自动改用新修订。批量推荐的两个值同时应用到全部所选作品，未勾选表示取消对应标记。

批量工具在选中作品后出现。关闭面板会清空本批选择，未完成的操作仍需确认放弃；关闭或清空后回到作品选择控件，所选作品已不在当前列表时回到搜索框。

批量请求使用 `POST /api/v1/admin/personas/bulk`，每项分别包含 `id`、`expectedRevision` 和唯一 `idempotencyKey`，共同的理由最多 2,000 字。各项独立校验身份、状态及修订并提交事务，返回成功或明确的错误；批量请求不承诺所有作品同时成功。

页面区分已确认成功和待核对项，重试只提交未完成项，并保留原操作标识。修订冲突项可单独读取最新状态，明确采用后再次确认。重试不会重复记录已成功的操作，结果不明确时不要重新选择全部作品重复处理。

## 管理记录

`GET /api/v1/admin/personas/:id/records` 每页最多返回 20 条记录，包含执行者用户名、动作、理由、时间、自审标识和相关快照入口。记录仅对有效管理员会话开放，响应禁止缓存，不返回请求标识、邮箱或私有正文。理由按原文以安全文本展示，长内容可独立滚动和键盘访问。
