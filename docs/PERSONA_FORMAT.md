# 人设通用文件格式 v1

本站通用格式用于保存两种平台的人设正文、作品资料、README、来源、转载许可与图片引用，和 MaiBot TOML、AstrBot 原生 JSON 分别定义。通用文件不会恢复本站账号身份、私有授权证据、审核状态、会话、互动统计或机器人能力配置。

本站导出的 JSON 和 ZIP 内文本统一为 UTF-8。独立上传的 JSON 可在导入向导选择 UTF-8、GBK/GB18030 或 UTF-16，预览会标明实际编码；这属于上传兼容处理，不改变 ZIP 内文档的 UTF-8 约定，正文空白和换行不会因转码而被裁剪。

在作品详情或历史版本的「导出」面板中选择「通用 JSON」，可预览并下载该公开版本的 `.persona.json` 文件。分类标签使用当时的名称，图片引用只来自该版本已批准的公开素材；后续私有草稿不进入文件。

选择「完整 ZIP 包」可下载 `.persona.zip`，其中包含根目录的 `persona.json`、`README.md`、`LICENSE.txt` 和清单声明的 `assets/` 图片。无图片时保留三个根文件；作品来源许可说明由该版本声明生成。下载支持取消，图片缺失或完整性校验失败时不会提供缺图包。

机器可读定义见 [persona-v1.schema.json](../packages/contracts/schema/persona-v1.schema.json)，由共享 Zod 契约生成，稳定标识为 `urn:uuid:4a2d4267-a0fa-4016-b9ef-90e4f4dfb7c8`。根 `format` 固定为 `qingzheng-persona`，`schemaVersion` 固定为 `1`；未知版本、未知字段及跨平台正文需要明确拒绝，不能猜测无损转换。

## 字段

| 字段       | 内容                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------- |
| `platform` | `maibot` 或 `astrbot`                                                                        |
| `content`  | MaiBot 三段正文，或 AstrBot 人格与有序的用户/AI成对对话                                      |
| `metadata` | 名称、简介、分类名称、标签名称、README、推荐模型、作者说明、来源与转载许可、头像和封面包内键 |
| `assets`   | 作品实际引用的静态图片清单                                                                   |
| `source`   | 可选的源站地址、作品地址、发布者显示名称、源版本和更新说明，仅作来源信息                     |

分类、标签按名称迁移，不能把源站内部 ID 当作本站有权使用的对象。对话不携带行 ID，导入时重新生成。`metadata.origin` 保留原作者、来源与许可声明；文件中的自称原创不等同于当前导入账号获得原创身份，使用者仍须核实来源、授权和发布责任。

字数按 Unicode code point 计数，保留作者原文、空白与对话顺序，拒绝孤立代理项和数据库无法存储的空字符。结构允许未填写完成的字段，提交公开版本时另按站点当前业务规则校验。绝对内容边界与编辑器一致：MaiBot每段20000字符，AstrBot人格100000字符、最多100对对话、单条20000字符，README30000字符，标签8个、推荐模型5条。分类与标签名称各80字符。

## 图片与介质

每项图片具有以下信息：

```json
{
  "key": "3cabba2c-340d-4edb-8357-a1404f6f878a",
  "mimeType": "image/webp",
  "bytes": 128,
  "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "path": "assets/3cabba2c-340d-4edb-8357-a1404f6f878a.webp"
}
```

以上为结构示例，字节数与哈希需要替换为实际文件值。`key` 是小写规范 UUID，仅用于文件内部映射，不恢复本站素材 ID。路径必须与键和 MIME 扩展名一致，不能包含任意目录或文件名。头像、封面及 README 图片必须存在于清单；清单也不能夹带作品未引用的文件，最多22项，其中README最多引用20张图片。

纯 JSON 将 `path` 替换为互斥的 `url`，README 使用 `asset://包内键` 引用清单；URL 仅作声明，解析时不联网。完整包使用 `assets/包内键.webp` 等相对路径，README 也使用对应相对路径；同一文件不能混用在线和包内介质。在线引用不保证离线可用，浏览器不能自动加载未经托管的外站图片。

只有静态 JPEG、PNG、WebP 属于图片范围，单图不超过5MiB。JSON Schema只定义结构，实际文件还须核验字节数、SHA-256、解码类型、像素边界、Markdown实际引用、资源归属和公开资格；CRC不能代替密码学哈希或授权验证。

JSON、文本及完整包中的人设清单最多4MiB；合法字段组合序列化后超过总预算也须明确失败，不裁剪正文。ZIP上传、解压总量与条目分别受128MiB、160MiB和128条边界约束，归档布局限定为根 `persona.json`、`README.md`、`LICENSE.txt` 和清单声明的 `assets/` 图片，归档解析还须拒绝穿越、链接、加密、重复名称、嵌套归档及超出实际解压预算的内容。

图片地址映射只替换Markdown真实图片URL或有效引用定义，保留代码、普通链接、标题、作者空白及换行。包内许可说明属于作品作者声明，不能把本站软件的 AGPL 许可证自动套到用户作品上。

v1 的 `LICENSE.txt` 由清单中的发布者、来源与转载规则生成，使用适配器 `marketLicenseText` 提供的固定声明模板，允许 LF 或 CRLF 换行。附加的作者条款写入 `metadata.origin.policyText`；许可文件与清单冲突时拒绝导入，避免漏掉或替换包内声明。README 与清单正文也须一致。

## 维护

修改共享契约后执行 `pnpm formats:generate`，提交生成的版本化 Schema；`pnpm check` 包含漂移校验。JSON Schema不能表达的跨字段与文件语义由适配器和业务权限校验补充，结构校验通过不代表内容已获授权或可以公开。
