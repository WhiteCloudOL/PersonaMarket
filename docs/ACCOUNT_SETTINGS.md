# 注册与账户设置

管理员在「站点设置 → 账号设置」管理注册开关、注册尝试频率和新会话期限。设置读取与变更记录要求有效管理员会话，保存涉及账号与会话策略，需要十分钟内的身份确认。未绑定 MFA 的管理员使用当前密码确认；已绑定的账号使用身份验证器或恢复码。验证过期时自动弹出窗口，身份确认后返回原表单，由管理员再次保存。

## 注册和邮箱验证

| 设置         | 默认值                                             | 含义                                                     |
| ------------ | -------------------------------------------------- | -------------------------------------------------------- |
| 注册开关     | 使用部署的 `AUTH_REGISTRATION_ENABLED`             | 关闭后不接受新注册；已有账号仍可登录、验证邮箱和找回密码 |
| 注册尝试次数 | 10次                                               | 每个 IP 在选定窗口内允许的尝试，范围1–10                 |
| 注册窗口     | 3600秒                                             | 范围60–3600秒                                            |
| 新会话有效期 | 使用部署的 `AUTH_SESSION_TTL_SECONDS`，通常86400秒 | 范围600–604800秒；已有会话保留原到期时间                 |

注册页先向邮箱发送 6 位验证码。验证码在 10 分钟内单次有效，重新发送会替换旧码。服务端验证通过后，在同一事务中消费验证码并创建已验证账号。验证码邮件使用加密 Outbox，由 Worker 发送。旧的发送时机配置仅用于兼容历史记录。

升级前已创建但未验证的账号仍可登录与编辑私有草稿，也可在注册页使用原用户名、原密码与新验证码完成验证。公开投稿、评论与互动、公开资料送审及远程图片等操作继续检查邮箱验证状态。

开放注册时，通过格式校验并进入业务处理的请求按“注册尝试”计数，后续因常见密码、冲突或其他原因失败也计入。关闭注册时不扣可配置业务窗口的预算，固定 IP 保护仍在。可配置规则之外，始终保留每 IP 每小时10次的硬上限。两层限制不会相加为更多可用次数。

同一窗口内降低次数会沿用已有计数；修改会话期限、邮件时机或设置修订不会重置计数。修改窗口后使用对应窗口的计数，切回尚未过期的旧窗口会继续使用其计数。等待剩余窗口后再试，不清空共享 Redis。

## 保存、冲突与记录

点击「保存注册设置」提交表单。客户端自动携带当前 `ETag`、幂等键、当前账号标识和 CSRF 令牌。设置、差异记录与审计在同一事务提交。

并发修改时，页面在后台读取当前设置并合并不同字段。同一字段发生冲突时保留你的输入，由你再次点击保存。网络结果不明时再次点击保存会先复用原幂等键确认结果。近期身份确认完成后，在原表单再次点击保存。

「变更记录」按修订倒序，每页20条，页码范围1–100，只有管理员可读。新记录同时冻结当时实际生效的值与原始存储来源；`null` 表示采用部署回退值。旧记录没有保存的新字段或当时有效值显示为未知，不能用今天的部署默认值补成历史事实。记录只读，没有回滚历史记录或直接改写审计的入口。

## API与客户端兼容

| 方法与路径（均以 `/api/v1` 为前缀）           | operationId                 | 用途                                                                                 |
| --------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------ |
| `GET /admin/settings/accounts`                | `getAccountSettings`        | 读取完整有效设置、部署默认值与修订，返回 ETag                                        |
| `PATCH /admin/settings/accounts`              | `updateAccountSettings`     | 提交 `{data}`，近期身份确认后保存                                                    |
| `GET /admin/settings/accounts/records?page=1` | `getAccountSettingsRecords` | 读取只读差异记录                                                                     |
| `GET /auth/context`                           | `getAuthContext`            | 原有身份信息外，返回 `registrationPolicy:{verificationEmailTiming,settingsRevision}` |

公开上下文只返回注册引导所需的时机与修订。网页请求会话上下文时使用 `registration=configuration`，只读取配置即可显示注册入口。实际申请验证码时会重新检查 SMTP 连接。默认的上下文请求仍会综合检查注册开关和 SMTP 可用性。上下文不公开管理员的限流细节、SMTP 连接或秘密。

旧 flat PATCH 的两个原字段仍必填，省略新字段时由事务保留当前已存策略，不注入默认覆盖。旧客户端可省略幂等键、账号核对头和理由，理由使用“更新注册与账户设置”；新界面使用完整请求。请求兼容不代表旧浏览器 bundle 无缝兼容：旧严格响应契约无法接受新增字段，升级后须刷新页面，并同步部署匹配的 API、Web 与生成客户端。

## 升级和恢复

`0048_account_policy.sql` 将48条迁移正常升级为49条，仅为 `accounts` 缺少的新键或嵌套成员补默认。它保留已有注册开关、会话期限、`null` 部署回退来源、自定义新值、设置修订与更新时间，不创建旧历史，也不静默修复非法既存值。旧已执行 SQL 不改写。

按[数据维护](OPERATIONS.md)先备份，再使用单一受控进程迁移并启动匹配版本。保留原备份和旧镜像；如需恢复，先停写并评估新增设置与历史兼容性，通过既有受控恢复流程操作，不直接删除迁移记录或改写已执行迁移。本次新增没有运行时环境变量，原有部署回退仍有效。

维护验证入口为独立的 `tests/integration/account-settings-upgrade.test.ts` 与 `account-settings.test.ts`。前者比较48→49升级、旧值/修订/时间/其他设置/账号摘要与重复迁移；后者使用隔离测试数据库、真实 API、Redis、持续在线的 Mailpit 与 Worker，检查注册、显式邮件、权限、正常配置禁用、CAS、幂等和并发。写有测试不代表运行通过，实际命令与结果以本轮验收记录为准。
