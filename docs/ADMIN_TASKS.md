# 失败任务

管理员可从账号菜单的「系统 → 失败任务」或管理概览的「查看失败任务」进入列表

类别选择立即更新结果；「按阶段筛选」先暂存选择，点击「应用筛选」后生效，取消保留原条件。类别、阶段和页码保存在 URL 中，可以刷新、返回或复制链接

列表优先展示任务类型、失败阶段和创建时间。点击「查看详情」阅读安全错误摘要、任务标识，以及分别记录的分发和执行尝试次数。旧记录没有持久化的次数显示为「未记录」，不推算为零或自动重试上限

每页最多 20 条，最多 500 页；超过 10,000 条时，列表明确提示显示范围，匹配总数仍取真实数据，不生成超出接口上限的页码

当前列表读取 PostgreSQL 中分发耗尽、图片导入、导入包图片、排行生成、通知和邮件投递状态，并核验当前队列保留的失败记录。同一业务优先采用数据库当前状态与消费回执，旧失败不会覆盖已经完成的业务，分发与执行失败不会重复相加

邮件确认未发送的失败与结果待确认分别展示。发送中长期没有确认、SMTP 结果不明，以及旧消费者缺少投递记录的失败，均不能推断为可以安全重发；请先核对原业务和邮件记录。邮件发送成功与消费回执共同确认后，旧队列失败不再计入待处理

「查看观测范围」提供队列采样时间、保留失败数量、本次检查和无法核验数量。每次最多读取最近 500 条保留失败；超出采样范围、任务契约或原始事件不匹配时标明部分观测。Redis 暂不可用时仍展示可读的数据库记录，保留失败总数显示为未知；此时「已知记录」和空结果均不代表全站没有失败任务。数据库列表的 10,000 条分页窗口和队列的 500 条采样是不同边界

数据库结果和队列采样时间分别记录，两者不是跨 PostgreSQL / Redis 的原子快照；需要最新信息时刷新列表。队列完成也不直接证明业务成功

错误信息只显示受控摘要和错误码，不展示邮件正文、收件邮箱、图片来源地址、私有内容或原始任务数据。任务页仅向有效管理员会话开放，审核员与普通账号不能读取列表或直接调用运维 API

通知的现有处理入口位于「通知管理」。重投账号安全类通知需要近期身份验证，系统根据账号实际绑定状态要求 MFA 或当前密码确认；只读列表不追加近期验证

## 图片任务运维 API

有效管理员可以使用 `POST /api/v1/admin/tasks/{source}/{id}/retry` 重新发起图片处理，`source` 为 `image` 或 `market_image`。请求包含列表中当前记录的 `expectedVersion`、5–500 字原因和 `confirmed: true`，并携带有效 CSRF Token 和 UUID `Idempotency-Key`；建议同时携带 `X-Expected-Account`

重试跨账号远程任务需要近期身份验证。服务端在事务内再次核验实际管理员、会话和 MFA 状态，检查所属账号、邮箱、业务锁、素材额度，以及导入预览是否有效。同一个幂等键重放返回原操作记录，不重复创建事件；同键不同请求返回冲突，过期版本按统一契约返回 `412 / REVISION_CONFLICT`

每个图片任务最多人工重试 3 次，相邻人工重试需间隔 60 秒；这与队列自动尝试次数分别记录。额度已满或冷却中返回限流提示。状态恢复、新 Outbox 事件和审计在同一事务提交，成功响应表示已创建重试请求，实际业务结果仍需刷新核对

`GET /api/v1/admin/tasks/{source}/{id}/retries` 提供最多 3 条人工操作记录、原因和操作者标识，只要求有效管理员会话。记录不可修改或删除，并保留原事件和新事件的关联，不展示图片来源地址或原始任务内容

其他任务仍应使用其原业务处理入口；邮件投递结果不明时不能通过此接口重发

## 排行、文件清理与邮件核对

排行、文件清理和邮件记录可从任务列表打开精确对象详情。详情选择保存在 URL 中；即使原失败行在受理后离开列表，当前对象、原因和原处理请求仍可在本次页面会话中核对。结果未知时先使用「核对原请求」，未查到回执不代表迟到请求不会完成；系统不会自动换标识提交。

排行恢复保留同一批次及其原算法、冻结权重和设置修订，不会改用今天的配置。只有可核验的终结失败可以创建受控重试；每批次最多三轮人工恢复，相邻轮次间隔60秒。已完成、自动处理中、事件谱系不明或已经裁剪的批次不会被强行重算。受理只表示新事件已创建，详情将分别显示当前执行事实与完整榜板是否已经核验。

文件清理分别记录「已删除」「原本不存在」「仍被引用而受保护」；历史消费记录没有结果时明确显示未记录，不补造删除事实。显式重查仍复核当前素材与导入预览引用，不接受任意路径，不允许强删受保护文件。同一个原清理请求跨新事件保留三轮/60秒上限。

邮件详情提供实际记录的用途、账号、令牌关联及时效状态，不展示正文、邮箱或原始令牌。人工核对仅追加说明，不重发、不取消已有自动任务，也不把SMTP未知改为成功；原业务失败记录可能继续显示。需要新验证或重置链接时由账号本人走原流程重新申请，旧链接按原业务失效。SMTP接受仍不等于已进入收件箱。

排行API为`GET /api/v1/admin/rankings/generations/{id}`、`POST /api/v1/admin/rankings/generations/{id}/retry`与`GET /api/v1/admin/rankings/generations/{id}/retry-receipt`；清理/邮件使用`GET/POST /api/v1/admin/operations/{kind}/{id}`与其`/receipt`只读接口，详见[OpenAPI](openapi.json)。这些内部处理使用有效管理员会话；已绑定MFA的账号仍须完成原登录验证。人工配额、冷却或业务状态变化不阻断只读原请求核对，角色撤销和会话失效仍立即阻断。
