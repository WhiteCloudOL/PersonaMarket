# 数据维护

## 存储与权限

所有业务与依赖服务数据集中在项目 data/，不使用 Docker 命名卷或匿名卷。目录绑定关系见 [部署说明](DEPLOYMENT.md)。

Redis 目录归容器 redis 用户所有，私有文件目录归应用 UID 1000 所有，默认权限 0700。data-init 调整 Redis 与私有目录本身，并将 Caddy 证书与状态目录递归归属 UID 1000，以支持从旧版 root 容器升级；操作保留文件内容，升级前先备份。应用与 Caddy 使用 UID 1000，应用镜像为无 shell 的精简运行环境，归档操作使用固定摘要的维护工具镜像。Linux 可用文件系统权限保护数据，Windows 还需限制目录 ACL；私有目录不作为 Web 静态目录开放。

## 状态与停止

```sh
docker compose -f compose.yaml -f compose.dev.yaml ps
docker compose -f compose.yaml -f compose.dev.yaml stop
```

停止或重建容器会保留 data/。不要删除数据目录来处理启动、迁移或权限错误。API 的 /health/live 和 /health/ready 只返回安全状态，Worker 以 Redis 心跳提供健康检查。

## 备份与恢复

1. 暂停业务写入并记录快照边界，确保数据库与私有文件对应同一状态。
2. 使用 PostgreSQL 工具备份数据库，归档 data/storage 和必要的 Caddy 状态；本地副本存放 data/backups。
3. 加密备份并离机保存，环境配置与加密密钥单独安全保管。
4. 先恢复到隔离目录 data/tests/ 和隔离数据库，校验数据、权限、迁移记录与文件完整性。
5. 完成验证后，由维护者受控切换到恢复副本；保留旧数据和回退方式。

备份应保留数据库对象权限。认证保护表与安全函数有独立授权，使用 `--no-acl` 会丢弃这些限制；跨环境恢复前先受控准备对应角色，再校验表、函数的权限和属主。恢复验证必须确认应用账户不能写入管理员保护表。

复制 PostgreSQL 原始文件必须在其正常停止后进行，且运行版本与平台保持兼容；跨主版本升级使用官方迁移或逻辑备份流程。Redis 只承担可重建任务状态，业务事实保存在 PostgreSQL。

## 历史命名卷迁移

已有安装迁移至 data/ 时，先备份配置、停写并正常停止服务，将旧卷以只读方式挂入一次性维护容器，归档后复制到空的目标目录，保留属主与权限。目标非空时停止并人工核对，不自动覆盖。

逐项校验数据库、Redis、私有文件及 Caddy 状态，再用新 Compose 启动并验证重启持久化。旧卷仅作为迁移来源和回退副本保留，正常运行不再使用它们；本项目不会自动删除旧卷。

## 更新

认证迁移新增 MFA 密文、恢复码哈希和安全审计表，升级只追加迁移，不修改已有账号。恢复时必须同时保留 APP_ENCRYPTION_KEY，否则 MFA 密钥与待投递邮件无法解密。加密密钥不与普通备份一起公开，恢复码明文仅在绑定完成时展示一次。数据库只存密码 PHC、会话/单次令牌/恢复码的用途隔离哈希，禁止把明文凭据加入日志或工单。

邮件 Outbox 以至少一次方式交付任务，投递状态由数据库记录。确认未发送的失败保留有限重试；SMTP 结果不确定、进程中断或接收后回执未确认时停止自动重发，先按[邮件投递](MAIL_DELIVERY.md)核对。单次令牌消费继续保持幂等，SMTP 接收记录不等于收件箱送达证明。Mailpit 收件箱仅用于本地测试，包含测试验证链接，应限制本机访问并按需清理 data/mailpit/ 内邮件，不能将其用于真实用户邮件。

更新前备份配置与 data/，审查 SQL 迁移及固定镜像版本，构建新镜像后执行 up -d --wait。迁移失败应阻断升级，不改写已执行的迁移，不在原业务目录上直接演练恢复。故障时保留日志和备份，按兼容性评估切回旧版本或经过验证的恢复副本。

## 人设与版本数据

工作草稿、Release、不可变送审快照、审核记录、公开指针和素材引用共同组成作品状态，备份与恢复需保留这些关联，不能只复制某张作品表。历史版本及授权证据引用的文件也需纳入私有存储备份，不能按“当前公开页是否使用”删除素材。

恢复后同时使用契约兼容的 Web、API 与 Worker 版本，核对迁移记录、草稿修订、快照摘要、资源归属和公开状态。审核、下架或撤回结果以数据库为准，不能直接改写旧快照来修正公开内容。

作品官方和精选标记保存在独立的 `persona_curations` 表，处理依据保存在管理记录，备份时须共同保留。该表的新增迁移不为既有作品添加默认推荐，不改写账号、草稿或发布快照。回退到兼容的旧应用时保留新增表和迁移记录，避免清除已经保存的运营标记；恢复新应用前先核对迁移完整性。

原生文件导入预览是当前账号的临时私有状态，有效期 30 分钟，Worker 按分钟分批清理过期预览。确认后形成的草稿独立持久化；临时预览不能作为作品备份。原始机器人配置可能含密钥，解析后只保存允许的人设字段，不将原文件写入长期存储或日志。

通用 JSON 与 ZIP 的预览使用独立短期记录和临时素材表，文件仍位于私有 `data/storage/`。正式与临时素材共用账号配额；确认事务同时转移素材和草稿，预览记录过期不影响已确认草稿。源站身份、审核状态和私有证据不会随文件恢复。

通用预览初始保留 30 分钟，用户实际确认或补充图片时可续期，创建起最多保留 60 分钟；读取与自动轮询不延长期限。图片下载和上传仍执行原有限流，续期不提高请求配额。

Worker 按分钟清理过期通用预览，并通过事务 Outbox 交付文件回收任务。失败任务有限重试，已经不存在的临时文件按幂等成功处理；删除前复查正式与临时引用。排查积压时同时检查预览状态、Outbox 和 Worker，不能按文件名或目录时间直接删除仍被引用的文件。更新时保留数据库和 Storage 的一致备份，使用配套 API 与 Worker 版本完成迁移。
