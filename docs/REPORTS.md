# 举报和处理

在公开人设详情选择「举报人设」，或在公开评论、回复中选择「举报评论」。登录后选择原因，填写问题位置、来源链接或相关线索，再提交举报。

举报原因包括侵权或来源问题、不当内容、垃圾广告和其他问题。补充说明最多 5000 个 Unicode 字符，保持原有空白和换行；页面按纯文本展示说明，不自动访问其中的链接。

## 查看自己的举报

从右上角账号菜单进入「我的举报」，按状态筛选、翻页，打开详情查看提交时的内容和管理员说明。

| 状态   | 含义                       |
| ------ | -------------------------- |
| 待受理 | 举报已提交，等待管理员核对 |
| 处理中 | 管理员已受理并继续核实     |
| 已处理 | 管理员记录了处理结果       |
| 已驳回 | 管理员核对后不予继续处理   |

举报保存提交时的公开版本引用、标题和简介；评论举报还保存当时获批的正文。待审评论、待审改稿和私有授权材料不会被复制进举报快照。目标后来隐藏或下架时，公开链接停止展示，原举报的私有记录继续保留。

举报详情和补充说明仅提交者本人及管理员可读，被举报者不能读取他人的举报。列表不展示补充说明，举报人的页面不返回管理员内部备注或管理员私有账号信息。

同一账号对同一份公开内容已有待处理举报时，无需重复提交；已结束的举报在提交后 24 小时内也不能重复创建。公开版本或获批评论正文更新后，可以针对新的内容举报。提交同时受每分钟 3 次、每日 UTC 20 次及共享来源限流保护，达到限制时按响应提示稍后再试。

## 管理员处理

在账号菜单的「审核」分组选择「举报处理」，默认查看待受理记录，按内容类型、状态或完整举报编号查找。详情分为「处理」「线索」「记录」：核对线索中的公开快照和私有说明后，在处理分区选择受理、完成处理、驳回或补充说明。切换分区会保留尚未提交的输入，关联管理入口可按需展开。

受理、完成和驳回需要填写举报人可见的说明，最多 2000 字。仅管理员可见的备注最多 5000 字；只填写内部备注的补充记录不会出现在举报人的记录列表或数量中。提交前的确认窗口会分别列出两种说明，便于核对可见范围。

选择「完成处理」后，可以保留内容仅记录结果，也可以封禁所举报的版本、下架整个人设或隐藏所举报评论，并可选择封禁被举报账号及是否同时下架其全部作品。封禁账号会撤销该账号的全部会话。内容与账号均来自原举报引用，不能在请求中指定其他资源。评论公开正文已经更新时，旧举报不能直接隐藏新正文，需要先在评论管理核对新版。

选择实际处置时，需独立填写「被处置者可见说明」，不要复制举报人的身份或私有线索。确认窗口分别列出举报人说明、内部备注、处置动作和被处置者说明；举报人记录只显示动作摘要，不返回被处置者说明或安全修订号。举报状态、领域处置记录、审计、幂等凭据和通知 Outbox 在同一事务保存，任一步骤冲突时全部回滚。

受理、驳回或仅记录其他人的举报使用有效管理员会话；实际处置内容或账号时需要十分钟内的身份验证。涉及管理员本人提交的举报或本人被举报内容时，还必须明确勾选自审确认。已绑定身份验证器的账号使用动态码或恢复码，未绑定账号使用当前密码确认；无需强制绑定 MFA。验证在当前页面完成，输入保留，由管理员手动重试。幂等重放仍重查当前权限和近期验证，不能用于绕过会话撤销或最后管理员保护。

其他管理员已经处理记录时，页面保留当前输入。选择「核对最新举报」，查看并采用最新修订，再重新选择合适的操作。请求响应丢失后可重试原操作；服务端根据幂等标识返回已有结果，不重复生成处理记录。结案后可以追加说明，不能重新受理或改变结案状态。

## API 和数据

| 接口                                     | 用途                                          |
| ---------------------------------------- | --------------------------------------------- |
| `POST /api/v1/reports`                   | 登录账号提交人设版本或公开评论举报            |
| `GET /api/v1/me/reports`                 | 本人的分页举报列表                            |
| `GET /api/v1/me/reports/:id`             | 本人的举报详情                                |
| `GET /api/v1/me/reports/:id/records`     | 本人可见的处理记录                            |
| `GET /api/v1/admin/reports`              | 管理员处理队列                                |
| `GET /api/v1/admin/reports/:id`          | 管理详情和当前 ETag                           |
| `GET /api/v1/admin/reports/:id/records`  | 完整处理记录和内部备注                        |
| `POST /api/v1/admin/reports/:id/actions` | 核对 `If-Match: "report-ID-N"` 后保存处理记录 |

写入需要有效会话、CSRF 和 UUID `Idempotency-Key`。管理员操作还需要 `confirmed: true`。列表和处理记录每页 20 条；管理员队列支持 `type=all|persona|comment|profile`、`status=all|pending|processing|resolved|dismissed` 和精确 `id`，本人列表只按状态筛选。可选 `X-Expected-Account` 只核对会话账号，不授予身份或权限。完整结构见 [OpenAPI](openapi.json)。

## 公开资料举报

从 [创作者主页](PROFILES.md) 提交资料举报时，必须同时指定作者账号 `userId` 和实际看到的获批快照 `submissionId`。当前待审资料、他人私有草稿和不再公开的快照不能新建公开资料举报。证据冻结当时的昵称、简介、公开链接和头像引用，不将邮箱或账号安全信息放入快照。

举报人通过 `GET /api/v1/me/reports/:id/avatar`、管理员通过 `GET /api/v1/admin/reports/:id/avatar` 读取冻结头像。资料下架或换版后，原公开头像地址失效，举报私有证据仍按举报权限读取；被举报者不能访问他人的举报证据。

管理员选择 `hide_profile` 处置时，服务器在同一事务核对资料修订和获批指针，并提交隐藏状态、资料记录、举报处理凭据及通知。旧举报不能直接隐藏之后审核通过的新资料，即使管理员重新读取了当前修订号也不能越过冻结目标核验。关联管理入口指向举报当时的资料快照。

所有接口禁止公共缓存，读取和写入受三秒 SQL 语句预算保护，繁忙时返回可重试的 503。状态、处理记录、审计和幂等结果在同一事务保存。数据库唯一约束防止重复的待处理举报，数据库触发器保护原始证据和追加式处理记录。

迁移 [0033_reports.sql](../packages/database/migrations/0033_reports.sql) 新增举报与处理记录表，[0034_notifications.sql](../packages/database/migrations/0034_notifications.sql) 提供私有通知及 Outbox 投递基础，[0035_report_resolutions.sql](../packages/database/migrations/0035_report_resolutions.sql) 新增只追加的处置凭据和独立版本状态修订号，不改变发布快照。版本即使封禁后再恢复，旧修订也不能通过并发校验。举报和私有说明属于数据库备份范围，数据维护沿用现有 [数据维护](OPERATIONS.md) 流程。
