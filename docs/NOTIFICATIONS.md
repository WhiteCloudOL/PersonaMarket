# 通知中心

从账号菜单进入「我的通知」，查看自己的审核结果、公开回复、作品及评论状态、举报进展、账号安全提示和管理员通知。通知按实际送达时间排序，每页20条，可筛选未读、标记单条或全部已读。

长通知可展开完整正文，内容按纯文本显示。公开回复只在审核通过且接收者有权访问时提醒；待审文本不会进入其他人的通知。相关内容后来不可访问时，原通知记录保留，跳转入口停止提供。

「全部已读」以当前列表取得的送达边界为准，后来送达的消息保持未读。其他账号无法读取、标记或修改你的通知；退出或切换账号时，私有查询缓存按会话规则清理。

## 邮件偏好

在通知中心展开「通知偏好」，可选择是否接收作品提交和审核结果邮件。修改采用修订检查；发生并发冲突时，读取最新修订会保留你的选择，由你核对后再次保存。关闭折叠区域不会丢失当前选择。

关闭此偏好不会关闭站内通知或必要的账号安全邮件，已经进入队列的邮件按原任务继续投递。密码重置、密码或邮箱变更等安全流程继续使用原有受保护邮件通道。未保存的偏好只保留在当前页面，不写入浏览器长期存储。

## 管理员操作

管理员从账号菜单的「运营」分组进入「通知管理」。「投递记录」用于核对排队、送达、跳过或失败状态；「写通知」通过完整用户名查找正常收件账号，核对内容后发送。切换分区保留未保存输入。

创建通知、普通通知重投及浏览管理页面使用有效管理员会话。安全类失败任务重投还要求十分钟内的身份验证：已绑定MFA的账号必须完成MFA，未绑定时使用当前密码。验证在当前面板完成，操作者核对后重新提交；幂等重放也重新检查实际权限和近期验证。

每位管理员每日最多创建100条通知，写接口另有限流。业务失败任务仅展示接收账号、类型和任务状态，不展示原文、私有目标或举报证据。失败通知重投保留原内容和业务标识，再次核对接收资格，并保存审计记录。CAS和幂等标识防止并发或断网重试创建重复通知。

从任务中心打开具体通知后，可按通知标识核对排队、送达、跳过或失败的当前状态，不必翻页寻找失败记录。精确详情只包含运维元数据，不展示业务通知正文或目标。分发尝试和执行尝试分别记录，缺少可靠记录时显示为「未记录」。自动处理中、账号不可接收或当前事件无法核验时，不提供新的重投操作。

重投被接受只表示已重新排队。当前事件的消费回执及业务状态用于核对送达或跳过；任务从失败列表消失、队列完成或旧事件有回执，都不代表当前通知已送达。跳过表示当时接收账号或目标不再可用，不能强制送达。

网络结果未知时，保留原幂等标识和原修订，通过「核对原请求」查询是否受理，再读取当前投递状态。查询没有记录并不能证明迟到的原请求不会执行；如仍需提交，应由操作者明确重试相同标识和载荷，不能自动换标识重发。账号安全通知的原请求重试仍要求实际近期身份验证；只读核对本身不会重新投递。原请求回执没有保存历史轮次的事件标识，因此只证明原请求曾受理，不能据当前事件重建过去的投递历史。

## API 与投递

| API                                                            | 用途                                                                                    |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `GET /api/v1/me/notifications`                                 | 本人已送达通知，`page` / `status=all` 或 `unread`                                       |
| `GET /api/v1/me/notifications/count`                           | 未读数及本次送达边界                                                                    |
| `PATCH /api/v1/me/notifications/:id/read`                      | 标记本人单条已读，严格空请求体                                                          |
| `PATCH /api/v1/me/notifications/read-all`                      | 按`throughId`边界标记已读                                                               |
| `GET /api/v1/me/notifications/preferences`                     | 本人邮件偏好及修订，默认修订0                                                           |
| `PATCH /api/v1/me/notifications/preferences`                   | `reviewEmail`及`expectedRevision`更新                                                   |
| `/api/v1/admin/notifications`                                  | 管理通知列表、创建及详情                                                                |
| `/api/v1/admin/notifications/recipients/lookup`                | 按完整用户名查找收件账号                                                                |
| `/api/v1/admin/notifications/:id/retry`                        | 失败的管理员通知重投                                                                    |
| `/api/v1/admin/notifications/failures/list`                    | 业务失败任务的脱敏元数据                                                                |
| `/api/v1/admin/notifications/failures/:id/retry`               | 业务失败通知重投                                                                        |
| `GET /api/v1/admin/notifications/deliveries/:id`               | 按通知标识核对四种投递状态及处理资格                                                    |
| `GET /api/v1/admin/notifications/deliveries/:id/retry-receipt` | 用原`Idempotency-Key`及`expectedRevision`核对当前管理员的原请求，返回是否受理及记录时间 |

写请求需要CSRF保护；创建和重投还需要UUID格式的`Idempotency-Key`。客户端可通过`X-Expected-Account`拒绝跨账号操作。结构及完整错误响应以[OpenAPI](openapi.json)为准。

两个精确读取接口只允许有效管理员会话，并设置`private, no-store`。原请求核对将幂等标识放在请求头，不能放进分享URL；读取按独立的读限流处理，不占用新投递的写额度。实际通知类型决定管理员通知或业务通知的请求命名空间，其他管理员无法用同一标识核对你的操作。

业务事务同时写通知和Outbox，Worker按至少一次语义消费；接收者、类型和业务来源构成数据库唯一键。队列只携带事件和通知标识。投递前重新检查账号及目标资格，未送达的通知不进入收件箱；任务有限重试，失败持久化并可受控重投。

新安装及升级需由单一迁移进程执行全部版本化SQL，包括0034通知基础、0035举报处置及0036通知偏好。迁移不会自动创建演示数据；不要修改已执行迁移或用数据库重置代替升级。
