# 模型建议

在「网站设置 → 模型建议」维护创作者可以主动选择的模型信息。使用有效管理员会话即可管理，普通用户和审核员不能读取管理记录或修改列表。

## 维护列表

1. 添加模型建议，填写模型标识和可选备注
2. 用上移、下移按钮调整顺序，关闭开关可以停用建议
3. 点击「保存模型建议」，修改记录可查看列表差异

最多维护 100 条，模型标识为 1–200 字，备注最多 500 字，均使用单行文字。列表内模型标识不区分大小写地检查重复，顺序决定创作者看到的排列。定位条件只筛选当前列表，不改变保存范围。

初始列表为空。停用项和管理理由不会出现在公开建议接口中；移除建议也不会改写作者的草稿、已提交版本或公开作品。

默认设置预览会列出当前输入和空列表，确认只填入表单，仍需点击保存。修改记录显示修改人和前后列表。

## 创作者使用

创建和编辑人设时，在「推荐模型 → 站点模型建议」选择一项，将模型标识和备注追加到当前表单。原有模型信息保持不变，添加后仍可修改；最多填写 5 条。

也可直接选择「添加推荐模型」，自由填写名称和备注，管理员建议名单不构成创建、保存或发布门槛。建议无法读取时可以重试，手动填写仍可用。

建议只提供填写便利，模型的供应商、可用状态和表现由使用者自行核对。站点不因此向供应商发送请求，也不收集模型 API Key。模型信息进入市场元数据和本站通用包，原生格式的支持范围见导出预览。

## 保存和冲突

保存失败后保留输入，核对状态后手动重试。另一页面先保存时会提示修订冲突，可读取并比较最新列表，再明确采用其修订号，当前输入会保留，最后手动保存。

重试返回的内容与当前输入不同时，会先展示最新修订供核对，并保留当前输入；确认采用修订号后再手动保存。

未保存的设置在同一账号的页面切换间暂存在内存，完整刷新会丢失；退出、切换账号或失去管理权限会清理私有缓存。不要把内存暂存当作服务器备份。

## API 和维护

| 入口                                                          | 用途                             |
| ------------------------------------------------------------- | -------------------------------- |
| `GET /api/v1/site/model-suggestions`                          | 按顺序读取启用的模型标识和备注   |
| `GET /api/v1/admin/settings/model-suggestions`                | 管理员读取完整列表、默认值和修订 |
| `PATCH /api/v1/admin/settings/model-suggestions`              | 保存列表                         |
| `GET /api/v1/admin/settings/model-suggestions/records?page=1` | 分页核对只读修改记录             |

写入使用 CSRF、`If-Match: "models-N"` 和 UUID `Idempotency-Key`，并在事务中核对实际管理员身份。公共读取不缓存私有信息，响应只包含启用项和修订号；管理记录不允许覆盖或删除。

迁移 `0031_model_suggestions.sql` 增加空默认列表，已有同名配置会保留。运行数据继续使用现有 PostgreSQL 和 [数据维护](OPERATIONS.md) 中的备份方式。
