# 分类和标签管理

管理员从账号菜单进入「分类管理」或「标签管理」，可以按名称、完整 ID 或启用状态查找目录，在面板中调整名称、排序和启用状态，并查看草稿、版本引用数量与管理记录。

名称最多 80 个 Unicode 字符，不含首尾空格或控制字符；同类名称不区分大小写，归档后仍保留名称，重新使用时恢复原条目。排序值范围为 -10,000 到 10,000，较小数值优先，同值按名称和 ID 稳定排列。创作选项和探索筛选沿用这份顺序，每类最多同时启用 100 个、累计保留 1,000 个条目。

停用后，该条目不再出现在新作品的选择项中，使用它的草稿仍可编辑，但再次送审前需要选择有效目录。已送审快照保留当时的名称，重命名、停用不会改写历史版本，也不会自动下架原有作品。

## 归档和恢复

未被任何草稿或送审版本引用的条目可以归档；存在引用时请使用停用。归档不删除名称、ID 或操作记录，恢复后保持停用，核对内容后再明确启用。

每次创建、调整、归档或恢复都需要填写处理理由。归档和恢复先展示确认内容，再提交实际请求。网络失败时保留输入；发生并发冲突时，先读取最新目录、核对差异，明确采用最新修订后再手动提交。

## API

分类和标签分别使用 `/api/v1/admin/categories`、`/api/v1/admin/tags`，提供列表、创建、详情、修改、归档、恢复与分页记录接口，完整结构见 [OpenAPI](openapi.json)。

读取及维护目录使用有效管理员会话，操作在事务内再次校验身份。写入需要 CSRF、UUID 格式的 `Idempotency-Key`；除创建外，还需要资源对应的 `If-Match`，例如 `"category-条目ID-修订号"`。`X-Expected-Account` 可核对当前账号，不能授予权限。

相同幂等键重试相同请求只执行一次，改变请求后复用键返回冲突。修订过期返回 `412 REVISION_CONFLICT`，名称重复、条目被引用或超过数量上限返回 `409 CONFLICT`。操作记录只读且追加，包含操作人、理由和变更前后目录状态，不包含邮箱或账号凭据。

## 数据维护

目录管理使用新增的 `0028_taxonomy_management.sql`，为原有分类和标签补充排序、修订、归档时间与更新时间，并新增管理记录。原有条目保持原 ID、名称及启用状态，历史草稿和送审快照保留原文。

迁移发现同类目录存在不区分大小写的重名时会回滚并阻止启动，不自动改名或删除。维护前按 [数据维护](OPERATIONS.md) 保留一致备份；如需恢复，应同时恢复应用版本和对应数据库备份，不能只删除迁移记录或直接删除已被引用的目录。
